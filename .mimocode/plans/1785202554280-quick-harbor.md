# Merge dev-Caio into dev-Sanderson – Rollback to a stable commit

## Goal
Revert the repository to commit `834b299` (the clean React 18/Vite/TypeScript scaffold) to regain the previous high‑quality state, while preserving the work currently in `dev-Sanderson`.

## Approach
1. **Safeguard current work**
   - `git stash push -m "temp: work in progress"` – store uncommitted deletions/modifications.
2. **Create a temporary branch at the target commit**
   - `git checkout -b temp-original 834b299`
   - Verify `git status` shows a clean tree.
3. **Export the clean state for reference**
   - `git checkout temp-original -- .` (or copy the whole directory) – now the working tree contains exactly the files from that commit.
   - Optionally, `git diff --name-only temp-original...dev-Sanderson` to list differences.
4. **Re‑integrate needed changes into `dev-Sanderson`**
   - `git checkout dev-Sanderson`
   - `git stash pop` (restore the stashed changes) or manually copy over the files that were previously deleted/modified.
   - Resolve any conflicts, run the app (`npm run dev`) to verify functionality.
5. **Commit the re‑integrated changes**
   - `git add .`
   - `git commit -m "Re‑apply dev-Sanderson changes on top of 834b299 scaffold"`.
6. **Cleanup**
   - Delete temporary branches: `git branch -D temp-original`.
   - Verify no stray stash entries remain: `git stash list`.

## Verification steps
- After re‑applying changes, run `npm install` followed by `npm run dev` to ensure the site launches without errors.
- Check that all previously working components (Navbar, Preloader, CustomCursor) render correctly.
- Confirm that the custom cursor and reveal animations behave as before the merge.

## Risks & Mitigations
- **Loss of uncommitted work** – mitigated by stashing before checking out the old commit.
- **Merge conflicts** – resolve manually; the plan uses `git stash pop` to re‑apply previous changes on a clean base, which usually produces conflicts only on files that were edited in both branches.
- **Broken build** – run the dev server after re‑integration to catch errors early.
